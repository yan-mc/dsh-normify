## 00:40–01:40 ｜ Normify 是什么：把架构变成"可被机器校验的数据"

**【口播】**
"Normify 是 DeepSeek Harness 的一个插件。它做的事情可以用一句话说清：
**把项目架构写成一份归一化的、分形的模块树数据，然后用零容忍的校验去守住它，最后渲染成一张单文件的交互式架构图。**

三个关键词：
**归一化**——同一个项目，不管谁写、在哪台机器上生成，结构数据的格式与顺序完全一致，可以 diff、可以回滚、可以冻结。
**分形**——每一层长得一样：一个模块要么是叶子（有 API、有代码证据），要么是容器（只有子模块）。根节点也是模块。
**零容忍**——结构数据不允许'大概对'。写的时候校验、全项目校验、编译冻结三道关，任何一条 error 都不产出产物。

它不是画图工具，是**给人和 AI 共用的架构协议**。"

**【画面】** 展示 `normify.html` 总览层，鼠标悬停节点、点开子层（下钻）。

## 01:40–03:10 ｜ 数据模型：一棵树，几个字段，撑起整个系统

**【口播】**
"一个模块长这样：`uid` 是 8 位随机串，**改名、挪层都不变**，它是模块的身份证；`id` 是路径式的点分 id，
既是名字也是位置，**深度不设上限**——想下钻到'单一功能单元'就一直下钻，不需要为了少建几个模块而含糊其辞。

`parent` 只存父级，子级靠反查——所以不会出现'父子互指'的不一致。
`leaf` 才允许声明 `apis`：每个 API 有协议、路径和双语描述。容器不允许有 API，这条是硬校验。
`deps` 只存**出向**依赖，四种语义：调用、事件、数据流、引用，可以跨树。

最关键的是 `source` 与 `fingerprint`：每个模块声明它由哪些源码文件实现，指纹是这些文件内容的 SHA-256。
**代码一改，指纹就对不上，校验立刻报 `fingerprint-drift`** —— 这就是'图和码不会脱节'的机制。
渲染数据是另一半：每个容器一层 `renders/*.json`，写这一层**怎么画**——阅读顺序、分组、模式、导语、车道。"

## 03:10–04:10 ｜ 三层校验：写时 / 全项目 / 冻结

**【口播】**
"Normify 的校验分三层，而且都是**fail-closed**（宁可拒绝，不放行）：

**L1 写时校验**：调任何写工具，立刻检查字段格式、id 合法性、parent 是否等于 id 去尾段、双语是否齐全、
叶子必须有 apis、API 键是否全局唯一、标签长度等等。不合法就整批不落盘——批量写入是**原子的**。

**L2 全项目校验**：跨模块的问题在这里。依赖指向不存在的模块、环、重复 API 键、文件映射、渲染数据与结构数据不一致、
以及'引导型'的提示：叶子是否过粗、层级是否过浅、**两端都有 API 的箭头却没锚定到具体 API**。

**L3 编译冻结**：`build` 只有 0 error 才产出 `tree.json` / `outline.md` / `api-index.json`，并把每个产物的
SHA-256 写进 `receipt.json`。文档说'这一版架构是什么样'，回执可以证明它没被改过。"

**【画面】** 终端里依次跑 `normify_validate`、`normify_build`，高亮 `0 error / 0 warning` 与 receipt 的 hash。

## 04:10–05:20 ｜ 31 个工具 + 一个技能：给 AI 的手脚

**【口播】**
"插件给了 AI **31 个工具**，按职责分族：读取（树、模块、检索、反查依赖、重建大纲）、
写入（初始化、创建/更新/删除/晋升/移动、原子批量、局部 patch）、
渲染数据（读/写/删某一层怎么画）、流水线（校验、编译、渲染、指纹、增量同步规划）、
伴随开发（开发指引、动手前预检、变更日志、架构规则）。

还有一个 **normify-gen 技能**：它告诉模型怎么写这份结构数据——粒度怎么切、每叶放几条 API、
先计划后实现的顺序。技能是'怎么想'，工具是'怎么做'，两者配套。

工具本身也很'AI 友好'：新会话里可以直接问 `normify_help`——
`fields` 看字段、`deps` 看依赖与 API 直连、`renders` 看渲染数据、`flow` 看主流程、
`tools` 看工具清单（带必填/可选），`tool:normify_module_batch` 直接打印某个工具的完整参数树。"

## 05:20–07:50 ｜ 核心场景：伴随开发（先立结构，再写代码）

**【口播】**
"Normify 最想解决的问题是：**让架构图成为开发的起点，而不是事后补的作业**。流程是这样的六步：

**第一步，初始化。** `normify_project_init`：建结构数据目录、装默认架构规则，可以顺手建一个'计划态根模块'。

**第二步，开变更。** `normify_change_open`：写清楚这次要干什么、涉及哪些模块、**验收标准是什么**。
它会落一份变更文件，跟着结构数据一起回滚。

**第三步，先建图。** `normify_brief` 给开发指引，`normify_check` 在动手前预检——
你要新建的模块、要加的依赖，先过一遍 parent、环、架构规则。然后 `normify_module_batch` 一次性建**计划态**骨架：
`state: planned`、`fingerprint: pending`，源码文件还不存在也没关系。每个叶子先把 **API 契约**声明出来。
这一步的意义是：**设计错误在写代码之前就暴露**。

**第四步，逐个实现。** 每写完一个模块，`normify_module_refresh` 把它的指纹算出来、从 planned 转成 active。
没落地的模块会一直挂着'未完成'，AI 想假装写完都装不了——因为激活时会检查源码是否真的存在。

**第五步，每层配渲染数据。** `normify_layout_upsert` 写这一层的阅读顺序、分组和导语——
等于逼你回答'这一层从哪看起、为什么这么排'。

**第六步，收尾。** `validate` 0 error → `build` 冻结 → `render` 出图 → `change_close` 强制 0 error 关单。
关单之前，验收标准要逐条自检。"

**【画面】** 全程录屏：终端里依次调用这六个工具，最后切到浏览器打开 `normify.html`，从最外层一路下钻到叶子。

## 07:50–09:00 ｜ 渲染器：一张单文件图里放多少信息

**【口播】**
"渲染出来的是一个**单文件 HTML**，没有依赖、可以离线打开、可以直接发给同事。

里面有几个细节值得一提：
**API 直连**——箭头不只连到模块框，还能**钉到具体的 API 行**：因为依赖可以声明 `from_api` / `to_api`。
叶子里的 API 默认**全部展开**（`max_api_rows` 缺省 0），这样就看得清'谁调了谁的哪个接口'。
**跨层聚合**——跨层级的依赖默认聚合成虚线 ×N，需要细节时再展开。
**防重叠**——走线只走自由通道，同一坐标不会分配给两条边；我们还有一个几何自检脚本，
逐层检查五项指标：越界、贴边、穿框、贴组框、线压线。上一轮自举图里'线压线'从 12 处降到 **0 处**。
**自适应**——viewBox 按全部几何算，线不会跑出视口。"

## 09:00–09:45 ｜ 架构规则：把'我们团队的约定'变成硬约束

**【口播】**
"`policy.yml` 是架构规则：禁止某些模块互相依赖、限制依赖方向（比如插件层 → 工具层 → 引擎层）、
检测环、限制层级深度（可选）、跨树依赖策略、命名规范。
规则默认是 error，直接**阻断编译**——不是'建议'，是'不许'。
项目创建时会自动写入一份默认模板，之后随时可以改。
**违规先改设计，不能绕过**——这是它和前几种'架构文档工具'最不一样的地方。"

## 09:45–11:00 ｜ 它真的有用吗：两轮 A/B 对照实验

**【口播】**
"为了不'自说自话'，我们做了两轮对照实验：同一个项目、同一份书面规范、同样的模型，
**一个 AI 带插件、一个不带**，最后用一套它们看不到的黑盒验收脚本打分。

第一轮是交互式白板后端：HTTP + SSE + 原子存储 + 幂等操作。
隐藏验收 42 项，两边都过了；但带插件那组**额外交付**了 41 个模块、110 条 API、10 层渲染数据，
而且它是在**写代码之前**就把 `store.lock` 这类并发关键模块画进结构里的。
不过那一轮也暴露了插件的四个易用性坑——比如 AI 为了拿准参数名只能去读插件源码。

第二轮换成表格公式引擎：词法、语法分析、求值、依赖图拓扑、循环检测。
隐藏验收 88 项，带插件 87/88、手写 88/88；两边自测都是 52/52。
差距只有一条：**有环工作簿的求值顺序**字段。同时我们还做了**差分模糊测试**——
六十份随机工作簿同时喂给两个实现，`check` 载荷 60/60 完全一致、无环场景 36/36 完全一致。
那一轮带插件那组的图纸里，**19 条依赖箭头 100% 锚定到了具体 API**。

每一次实验暴露的问题都变成了下一个版本：0.5.2 修三处'会写坏数据'的缺陷，
0.5.3 修四个'让人绕路'的摩擦点，0.5.4 修四个'工具侧'缺陷——包括一个最危险的
'返回成功但其实一个字段都没改'的静默失败。**这套东西是被真实使用打磨出来的。**"

**【画面】** 左右分屏对比两组产物：一边是结构数据 + 架构图，一边是代码目录；再贴关键数字表格。

## 11:00–11:40 ｜ 安装与适用人群

**【口播】**
"安装有三种方式：从 Release 下载 tgz 解到 profile 的 `node_modules` 并登记依赖与 bundle；
或者用 `dsh plugin add` 直接登记；开发模式可以用 `link:` 指向源码目录。
要求是 Node 18+、DSH 0.1.5+（DSHEAC AIO 6.9.x 桌面端实测可用）。
注意一点：插件是在**会话启动时快照**的，装完要新开一个会话。

它适合谁？三种人：
**第一，用 AI 写中大型项目的人**——你要的不是'能跑'，而是'三个月后还能改'。
**第二，需要交付架构文档的团队**——这份图是机器校验过的，不是手画的。
**第三，就是 AI 自己**——有了结构数据，模型知道边界在哪、改动会影响谁，而不是每次从零猜。"
